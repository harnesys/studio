# Дерево тредов, ветка по ссылке, видимость спавнов — дизайн

Дата: 2026-09-08
Статус: согласовано в чате (семантика форка, эфемерные спавны, подход 1, сайдбар без спавнов, хедер удаляется).

## Контекст

Ветка треда сейчас: новый пустой тред с `parentThreadId` + `forkAt`; родительские события не копируются и не подтягиваются. Агент ветки стартует с пустым контекстом, лента ветки пуста. Пользователь ответвился от ответа агента, переспросил — агент не знает, о чём речь. «Ветка» ведёт себя как «новый тред», ссылка на точку форка не используется нигде.

Спавн-сабагенты (runtime-механизм `control:spawn`) невидимы в UI: `eventToSessionEvent` выбрасывает `agent.spawned/completed/failed` (`packages/harnesys/src/application/run-engine-events.ts:290`), детские события discard-ятся в `graph-spawn.ts:141-143`, снапшоты детей пишутся под `sessionId = spawnId` без событий (`sqlite-runtime-state.repo.ts:58-60`). В ленте родителя спавн выглядит как молчание, потом JSON в state.

Сайдбар — плоский список тредов со значками «branch» и «N×». Хедер треда скопил кнопки навигации по веткам — пользователь просит убрать.

## Решения (зафиксированы)

1. Ветка наследует прошлое по ссылке: лента ветки показывает родительскую историю до `forkAt` включительно (read-only), агент ветки при запуске получает её как контекст модели.
2. Опорное сообщение (от которого ветвились) входит в контекст.
3. Спавны — эфемерные узлы без Thread-записей; видны в ленте родителя карточкой, просмотр — read-only вкладка.
4. Сайдбар: дерево тредов с ветками; спавны в сайдбаре не показываются.
5. `ThreadHeader` удаляется полностью; «открыть родителя» переезжает в разделитель в ленте ветки.
6. Техподход 1: единый event-лог + seed-контекст ветки при первом ране; события спавнов в общий лог треда с `runId = spawnId`; правки harnesys одобрены.

## Ментальная модель

- **Тред** — разговор с агентом. Единица навигации.
- **Ветка** — альтернативное будущее треда с фиксированной точкой. Постоянная структура, живёт в дереве сайдбара. Наследует прошлое, никогда — будущее: изменения родителя после форка в ветку не подтекают.
- **Сабагент** — делегированная задача внутри рана. Временная активность, не разговор с пользователем. Вывод в ленту родителя не течёт — только карточка-сводка; полный журнал доступен из карточки.

## UX

### Лента ветки

Унаследованная история рендерится приглушённо (opacity) и read-only: без hover-действий, без message actions. После опорного события — разделитель «⎇ ветвление отсюда · открыть родителя»: граница и путь назад в одном месте. Дальше — обычная активная лента ветки. Значки ветвления на сообщениях работают и в унаследованной части — дерево рекурсивно.

### Лента родителя

- На сообщении, от которого есть ветки: значок «⎇ N». Наведение — список веток, клик — переход.
- На месте `agent.spawned` в логе — карточка «Сабагенты»: строка на каждый спавн — имя целевого агента, статус (running / done / failed), последняя активность строкой. Клик по строке — спавн-вью. Карточка постоянна, после завершения рана остаётся входом к истории спавна.

### Сайдбар

Только треды. Ветка — под родителем с отступом (один уровень на глубину), рекурсивно. Корневые треды: pinned сверху, далее `updatedAt desc` (как сейчас). Ветки внутри дерева — `createdAt asc`, порядок ветвления. Все уровни раскрыты всегда. Значки «branch», «N× children», «← parent title» из меты строки удаляются — их работу делают отступ и значок ветвления.

### Хедер

`ThreadHeader` и его экспорт удаляются; `ide-content.tsx` рендерит ленту сразу в обоих местах.

### Спавн-вью

Новый `tab.kind = 'spawn'` со `spawnId`. Та же ленточная механика, события фильтруются `runId === spawnId` из лога треда. Без композера, read-only, заголовок вкладки — имя агента. Закрытие обычное; в сайдбаре и списке тредов спавн не появляется.

## Данные

### GetThreadUseCase (Studio server)

Для ветки: `events = [родительские до forkAt включительно] + [свои]`. Правило отсечки: найти в родительском логе событие с `id === forkAt` или `clientEventId === forkAt` — взять всё до него включительно; если `forkAt` — runId — взять до конца его рана включительно. Новое поле `inheritedEventCount: number` в `ThreadRecord` (Studio shared); клиент рендерит первые N событий как унаследованные. Порт `SessionEvent` (harnesys) не меняется.

### Первый ран ветки (Studio server)

Если тред имеет `parentThreadId` + `forkAt` и его snapshot пуст: собрать seed-messages из родительского лога до forkAt включительно (`user` → `role: user`; тексты ранов → `role: assistant`), закоммитить как первый snapshot ветки. Один раз, дальше ветка самостоятельна. Если родитель удалён — ветка продолжает жить со своим snapshot.

### Спавны: единый лог

- harnesys, `graph-spawn`: детские события эмитятся с `runId = spawnId` (снимается discard в `graph-spawn.ts:141-143`); `SqliteRuntimeState.child` прокидывает `onEvents` — события детей пишутся в `run_events` под `threadId` родителя.
- harnesys, `eventToSessionEvent`: `agent.spawned/completed/failed` возвращаются в SessionEvent-стрим (сейчас `null` при `handoff !== true`).
- Лента родителя группирует лог по `runId`; раны, чей `runId` совпадает с `agent.spawned.spawnId`, не рендерятся как обычные тиры — собираются в карточку спавна.

### GET /threads/:id/spawns (Studio server)

Список спавнов треда из run-lifecycle (`childrenByParent` по ранам треда): `{spawnId, agentId, status, parentRunId, startedAt, endedAt}`. Клиентский стор спавнов треда; карточка и спавн-вью берут данные из него и из лога.

### branchThread

Логика создания ветки не меняется (`parentThreadId` + `forkAt`, title по опорному сообщению).

## Удаления

- `ThreadHeader` (`apps/studio/client/src/widgets/chat-transcript/ui/thread-header.tsx`) и экспорт из `chat-transcript/index.ts`.
- Значки и меню-навигация по веткам в `agent-thread-row.tsx` (заменяются деревом).

## Не делаем

- Composer в спавн-вью, HITL внутри спавна.
- Отображение спавнов в сайдбаре и в списке тредов.
- Выбор «включить ответ или нет» при форке — всегда включено.
- Копирование родительских событий в run_events ветки.

## Порядок (набросок, детальный план отдельно)

harnesys: emit детских событий + agent.spawned в стрим → Studio server: seed, GetThread, /spawns → клиент: дерево сайдбара, карточка спавна, спавн-вью, разделитель ветки, значки ветвления, удаление хедера.

## Отклонения при реализации

1. `GET /threads/:id/spawns` не введён: список, статусы и активность спавнов выводятся из журнала (`agent.spawned/completed/failed`, детские события с `runId = spawnId`); отдельный endpoint избыточен. Раздел «Данные / GET /threads/:id/spawns» выше не действует.
2. Порт `RunEventStore` (harnesys) расширен методом `hasRun(runId)` (`sqlite-run-events.adapter.ts:165`): `StreamRunEventsUseCase` отдаёт 404 только если нет записи lifecycle и нет событий.
3. Спавн-SSE закрывается на первом терминальном кадре журнала для runId без lifecycle-записи; подписка до первого child-append попадает в окно 404, клиент переподключается.
