## 1. Actions (doc 16)

### Subpath export


`src/adapters/actions/index.ts` re-exports: `files`, `shell`, `fetch` (as `fetchTool`), `askUser`.

### Tool factories

Port from `/Users/mikestotik/Projects/Harnyx/packages/harnyx/src/adapters/actions/` with adaptation:

**Schema format**: Harnyx uses `zod` for input schemas. Harnesys uses `JsonSchema` (plain objects). Each factory defines input as a plain JSON Schema object. Runtime validation uses `ajv` (already in deps) inside each `execute()`.

**ToolContext adaptation**: Harnyx `ToolContext = { cwd, signal }`. Harnesys `ToolContext = { cwd, paths, signal, artifacts }`. The `paths.allow` array is used for path jail enforcement alongside the existing `root` option.

**Operations mapping** (doc 16):

| tools | operations |
|---|---|
| read_file, list_dir, glob, grep | `['fs.read']` |
| write_file, edit_file | `['fs.write']` |
| shell | `['process']` |
| http | `['network']` |
| ask_user | `[]` |

### askUser behavior

`execute()` throws a sentinel error `AskUserInterrupt` (defined in `src/domain/errors.ts`). The graph engine's tool-call handler catches it and emits `control:interrupt` with the resumeSchema from the tool input. Session layer maps this to `SessionEvent { type: 'ask', source: 'ask_user' }`.

Constants and schema from Harnyx `src/application/ask-user.ts`:
- `ASK_USER_TOOL = 'ask_user'`
- Input schema: `{ prompt: string, options?: { id, label }[], multi?: boolean }`

## 2. Skills (doc 17)

### Domain types

`src/domain/skill.ts`:
```ts
type SkillSummary = { name: string; description: string; whenToUse?: string };
type SkillDocument = SkillSummary & { instructions: string };
```

### FsSkillRegistry

`src/adapters/fs-skill-registry.ts`: implements Harnesys `SkillRegistry` port.

- Constructor: `FsSkillRegistry({ roots: string[] })` — scans `<root>/.agents/skills/*/SKILL.md`
- `list()` → `string[]` (names)
- `load(id)` → `SkillDocument` (typed as `unknown` per port)
- `reload()` → rescans all roots, last-wins on name collision

Port from Harnyx `src/adapters/skills/fs-skill-registry.ts` with interface adaptation.

### Parse skill file

`src/application/skills/parse-skill-file.ts`: YAML frontmatter parser using `gray-matter` (already in deps). Extracts `name`, `description`, `when_to_use`/`whenToUse`, `instructions`.

### Skills catalog helpers

`src/application/skills/skills-catalog.ts`:
- `filterSkills(registry, allowlist)` — returns filtered registry
- `formatSkillsCatalog(skills)` — markdown catalog string for prompts

### load_skill tool

`src/application/skills/create-load-skill-tool.ts`: factory returning `ToolDefinition` for `load_skill` tool. Reads full skill instructions by name.

### Wiring

`createRuntime` accepts `skills?: SkillRegistry`. When present:
- `reloadSkills()` calls `skills.reload()`
- `load_skill` tool is added to the tool registry
- Skills catalog is available for prompt assembly

## 3. MCP (doc 18)

### Domain types

`src/domain/mcp.ts`:
```ts
type McpStdioTransport = { type: 'stdio'; command: string; args?: string[]; env?: Record<string, string> };
type McpHttpTransport = { type: 'http'; url: string; headers?: Record<string, string> };
type McpSseTransport = { type: 'sse'; url: string; headers?: Record<string, string> };
type McpTransport = McpStdioTransport | McpHttpTransport | McpSseTransport;
type McpServerConfig = { serverId: string; transport: McpTransport; toolPrefix?: string; allowTools?: string[] };
type McpToolInfo = { name: string; description: string };
type McpResourceInfo = { uri: string; name: string; title?: string; description?: string; mimeType?: string };
```

### Internal ports

`src/application/mcp/mcp-connector.port.ts`:
- `McpConnection` — `listTools`, `callTool`, `listResources`, `readResource`, `close`
- `McpConnector` — `connect(config)`

### AiSdkMcpConnector

`src/adapters/mcp/ai-sdk-mcp-connector.ts`: wraps `@ai-sdk/mcp` `createMCPClient`. Supports stdio, http, sse transports.

`src/adapters/mcp/ai-sdk-mcp-connection.ts`: wraps `MCPClient` into `McpConnection` interface.

### Tool wrappers

`src/application/mcp/create-mcp-tool.ts`: wraps MCP tool as `ToolDefinition` with prefixed name (`serverId__toolName`).

`src/application/mcp/create-mcp-resource-tools.ts`: generates `list_resources` and `read_resource` tools.

### McpRegistry class

`src/adapters/mcp-registry.ts`: implements Harnesys `McpRegistry` port.

- Constructor: `McpRegistry(connector?: McpConnector)` — defaults to `AiSdkMcpConnector`
- `loadJson(json: CursorMcpJson)` — parses JSON, enables servers where `enabled !== false`
- `enable(id)` / `disable(id)` — connect/close individual servers
- `reload(id?)` — reconnect enabled servers
- `list()` — returns server IDs
- `tools()` — returns all `ToolDefinition[]` from enabled servers
- `closeAll()` — disconnect all

Port from Harnyx `McpServerManager` with interface adaptation to match Harnesys `McpRegistry` port.

### Wiring

`createRuntime` accepts `mcp?: CursorMcpJson | McpRegistry`. When `CursorMcpJson`, wraps in `McpRegistry`. `reloadMcp()` calls `mcp.reload()`. MCP tools are merged into the tool registry.

## 4. Artifacts (doc 19)

### FsArtifactStore

`src/adapters/fs-artifact-store.ts`:
- Constructor: `FsArtifactStore({ root: string })`
- `put(input: SendFile)` — if `path`, copy to store root; if `bytes`, write directly. Returns `{ uri }` (relative path).
- `read(uri)` — reads file from store root, returns `{ bytes, mediaType }`. Media type inferred from extension.

### MemoryArtifactStore

`src/adapters/memory-artifact-store.ts`:
- In-memory `Map<string, { bytes: Uint8Array; mediaType?: string }>` for tests.
- Same `put`/`read` interface.

### Fold attachments

`src/application/fold-attachments.ts`:
- `foldAttachments(files: SendFile[], readFn)` → model message parts
- Images/audio/video → multimodal parts (bytes)
- Files (kind:file) → text name+path only, no bytes

### Dependency swap

Delete `apps/studio/harnesys-stub/` directory.

### transcript.ts rewrite

`apps/studio/shared/transcript.ts`: rewrite `toTranscript` to accept `SessionEvent[]` instead of `Journal`.

Mapping:
- `text-delta` → `{ type: 'text', text }`
- `tool` (phase: requested/completed/failed) → `{ type: 'tool', call, result }`
- `ask` → `{ type: 'ask', askId, schema, source }`
- `done` → `{ type: 'done' }`
- `error` → `{ type: 'error', code, message }`

No mapper module. Transcript reads `SessionEvent` directly.

### workspace-harnesys.registry.ts rewrite

`apps/studio/server/adapters/workspace-harnesys.registry.ts`: use real `createRuntime` from `harnesys` with proper types. Import `files`, `shell`, `fetch`, `askUser` from `harnesys/actions`.

### thread-runtime.registry.ts rewrite

`apps/studio/server/adapters/thread-runtime.registry.ts`: use `SessionHandle` / `AgentRun` from harnesys instead of `ThreadHandle` / `AgentHandle`.

### Import updates

All server files that import from `harnesys` (currently stub) update to import from the real package. Types like `AgentRun`, `SessionEvent`, `SessionHandle`, `RuntimeState`, `Snapshot` come from the real package.
