How it works

  1. Create a workspace

    A workspace is a folder on your machine or VPS with its own SQLite database. Agents, threads, schedules, memory and settings all live inside it — move the folder, move the whole desk.

  2. Create an agent

    Pick a model, give it a job and instructions, choose what it may touch: files, shell, web search, memory, LSP. Start from presets — assistant, coder, researcher, orchestrator — or write your own.

  3. Put it to work

    Talk in a thread. Or let cron and inbound webhooks fire runs on their own. Long tasks show a live plan; anything irreversible waits for your answer in the Inbox.

What is in the desk

Agents and teams

Agents spawn subagents and hand work to each other. Children are sandboxed: they cannot ask you questions or change shared state, so a fan-out of thirty stays quiet and reviewable.

Real tools

Read and edit files, run shell commands with timeouts and allow-lists, search the web, call HTTP endpoints, query language servers for diagnostics and definitions. Every tool call is visible in the transcript.

Automations

Schedules are cron entries that fire a run into a thread; webhooks are URLs that wake an agent from the outside. Both get their own surface with the run journal underneath.

You stay in charge

Agents ask before they act. Questions land in the Inbox across all workspaces, waits can park a run for up to seven days, and budgets cap steps, tokens and wall-clock time per run.

Memory and knowledge

Pinned rules stay always visible, semantic facts carry between threads, past runs stay searchable, and indexed document folders answer questions with citations. The Memory tab is editable by you.

Built-in IDE

A file explorer with drag and drop, a Monaco editor, git branches and commits, PTY terminals and live LSP diagnostics — next to the chat, in the same window.

Any model

Bring keys for OpenAI, Anthropic, Google Gemini, OpenRouter, Groq, Mistral, xAI, Together, Kimi, Z.ai, Ollama, NVIDIA, Cerebras, MiniMax, Qwen, Moonshot and more — twenty drivers with remote model discovery. Reasoning effort, sampling and pricing are per model.

Spend you can see

A context bar shows what is used and what is left; every turn reports tokens and cache; the composer rolls up cost per run and per thread. Long threads compact with /compact.

Install

Three processes make a desk: harnesys-host runs workspaces, harnesys-web is a token-gated proxy for remote access, and harnesys supervises both.

Installs the host, the web gate and the CLI into ~/.local/bin.

shell
curl -fsSL https://github.com/harnesys/studio/releases/latest/download/install.sh | sh
shell
harnesys up --with-ui

Then open the desk, add a workspace and create your first agent. harnesys up --install-systemd keeps it running on a server; harnesys update moves you to the next release.

Images at ghcr.io/harnesys/host and ghcr.io/harnesys/web; a shared volume carries the host token so the gate pairs itself.

docker-compose.yml
services:
  host:
    image: ghcr.io/harnesys/host
    ports: ["3000:3000"]
    volumes: ["harnesys-data:/data"]
  web:
    image: ghcr.io/harnesys/web
    ports: ["8080:8080"]
    depends_on: [host]
volumes:
  harnesys-data:
