# Investigation: plan_item_update not found сразу после plan_save

Источник: самотест агента, память `e5d37a74`, п.1. Статус: open, нужен лог треда.

## Наблюдение

После `plan_save` (раунд 2) `plan_item_update` на id `b1540877-...` вернул `not found`, хотя тот же id был в `Valid ids` той же ошибки. Повтор позже прошёл.

## Что уже проверено

Гонка индекса в коде не видна: тул делает `get` и сверку в одном вызове (`../packages/harnesys/src/packs/plan/create-plan-tools.ts`), `savePlan` в `apps/studio/server/src/adapters/store/sqlite/repos/sqlite-plan.repo.ts:93-152` синхронный, `planId` переиспользуется. Ветка с `Valid ids` — предпроверка, при совпадении id она пройти не может. Подозрение: непробельный ввод или старый id до save.

Частично закрыто: `plan_save` теперь возвращает `items` с id, `plan_item_update` тримит ввод и принимает id/префикс/order.

## Нужно для закрытия

`threadId` прогона и точный текст обоих вызовов (сырой `itemId` первого, с пробелами). Без этого чинить нечего.

## Приёмка

Воспроизведение по логу либо подтверждение нормализации: повтор того же кейса проходит с первого раза.
